# 등기부 면적 실거래가 조회 (`real_estate_search/`)

등기부 PDF에서 뽑은 주소·면적으로 **같은 단지, 정확히 같은 면적**의 가장 최근 매매 실거래가 1건을 찾아 텔레그램 응답에 한 줄로 붙입니다.

```
KB시세 : 일반 265,000만원
KB시세 : 하한 247,500만원
KB시세 참고 : https://kbland.kr/c/62
실거래가 : 27억8,000만 26.05.04 24층 49.593㎡
```

- 데이터: 국토교통부 실거래가 신고자료 (KB시세와 별개 값, LTV 계산에는 쓰지 않음)
- 경로: k-skill-proxy `GET /v1/real-estate/{자산}/trade` — **API 키 불필요**
- 원래 `k-skill-main/real-estate-search` 스킬에서 필요한 조회 부분만 옮긴 것이라 `k-skill-main` 폴더가 없어도 동작합니다.

---

## 파일

| 파일 | 역할 |
|------|------|
| `molit_trade.py` | 프록시 호출, 단지·면적 매칭, 출력 한 줄 포맷 |
| `__init__.py` | 외부에서 쓰는 함수 export |
| `__main__.py` | PDF 한 건으로 결과 확인하는 CLI |

---

## 매칭 규칙

1. **법정동코드**: 기존 `KB_api.kb_price_api.KBPriceAPI.find_dongcode()` 10자리 → 앞 5자리(`lawd_cd`, 시·군·구)
2. **단지**: KB 조회로 확정된 `complex_name` 우선, 없으면 주소에서 추출. 공백·괄호·끝의 "아파트"를 뗀 뒤 같거나 한쪽이 다른 쪽을 포함하면 같은 단지
3. **면적**: 등기부 전용면적과 신고 면적이 **숫자로 완전히 같을 때만** 매칭 (`Decimal` 비교, 반올림·오차 허용 없음)
   - `49.593` ↔ `49.593` 매칭 / `49.593` ↔ `49.59`, `49.619` 매칭 안 됨
   - `84.93` ↔ `84.930` 은 같은 숫자라 매칭
   - `"51㎡/37.85㎡"` 처럼 공급/전용이 같이 있으면 전용(두 번째) 사용
4. **기간**: 지난달부터 최대 5년(60개월) 거슬러 올라가며 찾고, 동일 면적이 나온 가장 최근 거래 1건만 사용
   - 1년치(12개월)씩 병렬 조회 → 찾으면 그 이전은 조회 안 함
5. **자산 유형**: 아파트·주상복합 → `apartment`, 오피스텔 → `officetel`, 연립/다세대 → `villa`, 그 외 → `apartment`

비슷한 면적으로 대체하지 않습니다. 동일 면적이 없으면 없다고 표시합니다.

## 출력

| 상황 | 표시 |
|------|------|
| 동일 면적 거래 있음 | `실거래가 : 27억8,000만 26.05.04 24층 49.593㎡` |
| 5년 안에 동일 면적 거래 없음 | `실거래가 : 동일면적 거래 없음 (최근 5년)` |
| 프록시 호출 실패 | `실거래가 : 조회 실패` |
| 단지명·법정동코드를 못 찾음 | 줄 자체를 넣지 않음 |

---

## 웹훅 연동 위치

`api/webhook.py` → `format_registry_result()` (등기부 PDF 응답)

- KB 시세 표시 블록 바로 아래, `=========설정내역=========` 위에 한 줄 추가
- KB시세가 있든 없든 표시
- KB API를 호출하는 경우(`should_call_kb_api`)에만 실행 → **PDF 전용 방(`pdf_only`)에서는 호출 안 함**
- 텍스트 메시지 한도 산출 경로에는 붙어 있지 않음

## 조회 시간

| 경우 | 시간 (강남구 기준 측정) |
|------|------|
| 최근 1년 안에 동일 면적 있음 | 약 1~2초 |
| 1~2년 전에 있음 | 약 2.6초 |
| 5년 동안 없음 (최악) | 약 6초 |

요청 1건당 타임아웃 10초. 웹훅 `maxDuration` 60초 안에서 KB 조회와 함께 동작합니다.

## 직접 실행

프로젝트 루트에서:

```powershell
$env:PYTHONIOENCODING="utf-8"
python -m real_estate_search "temp/추인식 261022.pdf"
```

코드에서:

```python
from decimal import Decimal
from real_estate_search import find_same_area_trade, format_trade_line, lookup_registry_trade_line

# 주소·면적만으로 (법정동코드·단지명 자동)
line = lookup_registry_trade_line("서울특별시 강남구 청담동 134-38 청담자이아파트 제103동 제19층 제1902호", "49.593㎡",
                                  complex_name="청담자이", property_type="아파트")

# 법정동코드를 이미 알 때
trade = find_same_area_trade("11680", "청담자이", Decimal("49.593"))
print(format_trade_line(trade))
```

## 설정

| 환경변수 | 기본값 | 용도 |
|----------|--------|------|
| `REAL_ESTATE_PROXY_BASE_URL` | `https://k-skill-proxy.nomadamas.org` | 프록시 주소를 바꿀 때 |

상수는 `molit_trade.py` 상단: `MAX_MONTHS`(조회 기간), `MONTHS_PER_BATCH`(병렬 단위), `REQUEST_TIMEOUT_SEC`.

## 알아둘 점

- 국토부 신고는 계약 후 최대 30일 안에 하므로, 최근 1~2개월 거래는 아직 안 잡힐 수 있습니다.
- 신고 자료에는 동(棟) 정보가 없어 같은 단지·같은 면적이면 다른 동 거래도 잡힙니다.
- 구축 단지는 등기부 전유면적에 발코니가 들어가 신고 면적과 다를 수 있습니다(예: 은마 94.76㎡ ↔ 76.79㎡). 이런 경우 정확 일치 규칙상 `동일면적 거래 없음`으로 나옵니다.
- 프록시(`k-skill-proxy`)는 외부 서비스입니다. 장애 시 `실거래가 : 조회 실패`로 표시되고 나머지 응답은 정상 출력됩니다.
- `utils/real_transaction_api.py`(공공데이터 직접 호출, `REAL_ESTATE_API_KEY` 필요)는 이제 웹훅에서 쓰지 않습니다. 주소에서 단지명을 뽑는 함수만 이 모듈이 재사용합니다.
